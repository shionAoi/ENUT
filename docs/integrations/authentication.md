# Native sign-in wizard

Monitoring permission and provider authentication are separate. **Connect** remembers monitoring permission on this device, then checks native status using CLI-managed saved login. Gemini (backend ID `antigravity`) is the explicit exception: Connect asks for native-login consent and starts the existing owned `acp --login` process and code-entry modal. Only **Finish and connect** grants monitoring afterward. App restart restores grants without launching a login flow. Unknown login state, timeouts and unsupported quotas are not evidence of being signed out. No account probe occurs before consent, and no credential file is read to choose an action.

Only explicit native authentication-required evidence shows **Login**, replacing Connect rather than competing with it. Login asks for native sign-in consent before opening the wizard. Codex selects only ChatGPT/device-code and Antigravity only Google/native; other supported tools retain provider/method selection. Choose the actual account on the native/provider sign-in surface; existing credentials are not imported or enumerated by this monitor. Connected means observation success, not proof of authentication. Local metadata needs no provider login. An unavailable approved tool retains **Revoke access** in its details even when its primary action is retry Connect.

## Flows

- Codex: structured app-server ChatGPT device-code challenge. Enter the displayed code on the provider site. Only a matching completion plus confirmed ChatGPT account read produces `authenticated`. No paste-back form is offered.
- Antigravity: stable CLI >=1.5.0, `agy acp --login`, relayed through an auth-only pseudo-terminal. This preserves the native browser/manual-code prompts without inventing an ACP authentication protocol.
- Claude: `claude auth login` through the same terminal transport; paste-back input is available only as an explicit user action following native instructions.
- OpenCode V2: discover OAuth integrations/methods through the native API; run the explicitly selected `opencode auth login <integration> --method <method>` in the auth-only terminal. Methods needing extra form answers are not offered. Authorization codes are never passed through `api --data` or process arguments.
- Hermes: explicit provider selection, then `hermes auth add <provider> --type oauth`. Follow that provider's native device/browser/manual instructions. The wizard does not guess unsupported CLI flags or alter routing/onboarding settings.
- Ollama and LM Studio local inventory: login is not required.

## State and privacy

The native terminal has no shell, generic keyboard or command-execution API. While a native sign-in is waiting, **Return here after browser sign-in** shows the paste-back form without an extra expand step. For required Antigravity authentication, **Login → Allow native login** opens the modal and starts native login before granting monitoring. Return to EZTYN AI MONITOR, paste the browser authorization code or redirect URL, then select **Submit code to native tool**. The installed native tool owns credential persistence; the monitor does not persist the pasted code. Input accepts one bounded authorization code/redirect value only. Codex device codes belong on provider sites; its wizard never offers this field. Do not paste access tokens, API keys or passwords. Native terminal completion is labeled `finished`, not authenticated. **Finish and connect** explicitly enables monitoring and checks quota access; cancelling, Escape, failures and expiry never grant monitoring. Saved native credentials may persist beyond monitor exit; Cancel is not logout.

Starting login pauses monitoring for that tool without deleting saved history, cancels in-flight status work and waits for it to stop. The saved grant is paused too, so cancel/restart cannot silently regrant access after an account change; explicit Connect restores it. Grants are blocked until authentication finishes/cancels. Explicit Revoke deletes the tool's monitor-owned history and remembered grant, not CLI credentials or transcripts. Attempts are backend-owned, expire after15minutes, reject stale IDs and are cancelled on explicit revoke, replacement or application Quit. The code field is cleared after submission/closure; exact submitted terminal echoes are redacted. Authentication output is transient text only, bounded and escape-filtered, never part of usage snapshots or browser storage. Unknown transformed echoes cannot be generally detected; do not paste passwords/API tokens into this field.

Browser opening by the monitor accepts only the active Codex device challenge at HTTPS `auth.openai.com/codex/device`; native tools may open their own provider browser after explicit Start consent. The monitor never follows arbitrary output links or opens a frontend-supplied URL.

Synthetic protocol/PTY tests are not proof of live-provider compatibility or native Windows login. Unsupported versions, changing terminal prompts or account-specific provider requirements must fail visibly; there is no model/inference fallback.
