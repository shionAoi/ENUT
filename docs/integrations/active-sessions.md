# Native active sessions in Usage

Usage shows the selected tool's **currently executing native work**, independently of recorded token totals. All tools keeps its quota/reset summary; Usage does not duplicate it. No tracking hooks, inference requests, transcript reads for session detection, process-name heuristics, or loaded-model guesses are added.

## Supported sources

- **OpenCode V2:** fixed `opencode api get /api/session/active` (`session.active`). The official [API](https://opencode.ai/docs/api) and [OpenAPI schema](https://opencode.ai/docs/openapi.json) define `{data: {sesID: {type: "running"}}}`. This reports foreground drains owned by the connected service process, **not every OpenCode service**. The native API CLI uses normal discovery/authentication and may start a compatible background service if none is available. A new service's empty result says nothing about another service's work.
- **Claude Code:** fixed `claude agents --json`. The official [agent-view JSON table](https://code.claude.com/docs/en/agent-view#list-sessions-as-json), also verified through Context7, defines a JSON array with required `cwd`, `kind`, and `startedAt`; background rows have `id`/`state`; live processes have `pid`/`status`; `sessionId`/`name` are optional. Only live `status: "busy"` counts, with `state: "working"` additionally required for background rows. `working` alone can include sleeping loops or CI waits and is not executing evidence. Waiting, idle, exited and completed rows do not count. A busy interactive row without a session UUID uses its validated native process ID as a process label, not a stable conversation identifier; duplicate labels fail closed. Unsupported versions and non-TTY/compatibility failures remain unavailable. The documented schema, not files under `.claude/jobs`, is the boundary.

Both adapters accept at most 256 complete rows, validate bounded safe IDs, reject unknown status values and malformed/partial enumerations, and expose only ID plus `running`, source, scope and observation time. OpenCode requires `ses`-prefixed IDs. Titles, directories, names, account identifiers, prompts and tool output are not published. Existing bounded process execution uses fixed arguments, null stdin, neutral working directory, redacted errors, a 1 MiB output bound and 20-second timeout.

Successful empty native enumeration is **0 running**, within the displayed scope only. Missing/null, malformed or failed enumeration is **Unavailable**, never zero. Usage hides session IDs/source/scope/time without permission, on disconnection, on failed status, or when the session observation is 180 seconds old (the existing freshness threshold). Token-source success does not imply session-source success, or vice versa.

## Unavailable sources

- **Codex:** a fresh app-server cannot enumerate other processes' live sessions. Saved token records are not active-session evidence.
- **Gemini / Antigravity:** native quota metadata does not report active sessions or session tokens.
- **Hermes:** configured-provider quota windows are not consumed tokens or verified native running-session enumeration.
- **Ollama / LM Studio:** running runtimes and loaded models are not conversations.

These limitations are explained in the selected tool's Usage section, including before permission is granted; cached metadata is never included in that explanation.

## Reading tokens and actions

Recorded total/input/output/cache counters retain their actual source and period. Input is supplied to a model; output is generated by it. Cache semantics depend on the source and may overlap input; counters must not be summed to invent another total. Source totals are not current-session consumption, billed totals, or lifetime totals. Partial Claude input remains partial; missing metrics remain unknown.

The model chart uses available saved token records over the selected 7 or 30 UTC days, not active sessions. Missing dates are unknown, not zero. Whole-source model totals remain separately labelled with their source-period boundaries and are not recast as daily history.

Login/Connect/Revoke use the shared connection-action policy. Login needs explicit native authentication-required evidence. Connect remembers monitoring permission and checks reusable native state; explicit Gemini Connect instead starts the owned native login/code modal before granting. Startup never opens login. Unknown authentication does not suppress approved supported local token evidence. Saved history can render offline, but active-session evidence is never persisted/restored. Revoke deletes monitor-owned history and remembered access; it does not sign out of the native tool.

## Authoritative source evidence

Checked against public official documentation on 2026-11-11; no actual account or session command was executed for this check.

- [OpenCode OpenAPI, `/api/session/active`](https://opencode.ai/docs/openapi.json), operation `session.active`: **"Retrieve foreground Session drains currently owned by this OpenCode process. Sessions absent from the result are inactive."** The response is a closed object with required `data`; `data` is a map whose keys match `^ses`, with no additional properties. Its complete `SessionActive` schema has a required `type` whose sole value is `running`, with no additional properties. This establishes connected-process scope and complete enumeration within that scope, not machine-wide coverage.
- [Claude JSON enumeration](https://code.claude.com/docs/en/agent-view#list-sessions-as-json): **"`claude agents --json` prints active sessions as a JSON array and exits: every live session, plus background sessions that are still working or blocked even when their process has exited. Add `--all` to also include completed background sessions, and `--cwd <path>` to limit the list to sessions started under that directory."** This JSON-mode contract, unlike the interactive agent-view list, includes live interactive rows. The monitor passes neither `--cwd` nor `--all`; its neutral working directory is not itself a documented JSON-mode filter. This is enumeration for the CLI configuration/environment in use, not a promise about other users or configurations.
- The same Claude table marks `sessionId` and `name` as **"When set"**, and `pid`/`status` as **"While the process is alive"**. Its `working` explanation says **"`status` tells you whether its process is `busy` right now"**. Therefore UUID absence is supported, and `working` without a live busy status is not counted as executing work. The page does not provide a published JSON Schema or a minimum compatible version; unrecognized output remains Unavailable.
